# Swagger для CRUD API

Документация описывает 22 реализованные HTTP-операции из
`internal/http/handlers/quiz`, работающих с `internal/domain/quiz`.
Схемы ответов строятся по HTTP DTO: публичные ответы не содержат `is_correct`,
профили пользователей не содержат хеш пароля.

После запуска quiz-service с настроенным PostgreSQL:

```sh
go run ./cmd/quiz-service
```

- Swagger UI: <http://localhost:8080/swagger/index.html>
- Спецификация через HTTP: <http://localhost:8080/swagger/doc.json>
- Файлы спецификации: `docs/swagger.json` и `docs/swagger.yaml`.

Если задан `QUIZ_HTTP_PORT`, используйте его вместо `8080`.
Swagger отправляет запросы на тот же хост и порт, с которого открыта страница.

Для защищённых операций получите токен:

```sh
curl -X POST http://localhost:8080/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"alice","password":"secret123"}'
```

Пользователя можно создать через `POST /auth/register` с теми же полями.
В Swagger нажмите **Authorize** и вставьте значение `token` целиком:
`Bearer <JWT>`. Изменять вопросы и ответы, а также просматривать `is_correct`
может только автор соответствующего квиза. Новые операции редактора возвращают `403` при недостаточных правах и `401`
при недействительном токене. Старые операции вопросов и ответов пока используют `401`
в обоих случаях.

После изменения аннотаций или DTO пересоздайте документацию из корня проекта:

```sh
go generate ./docs
```

Версия генератора закреплена в `docs/doc.go`; отдельно устанавливать `swag`
не требуется. Команда обновляет `docs.go`, `swagger.json` и `swagger.yaml`.
Эти файлы следует коммитить вместе с изменениями обработчиков.
Формат аннотаций описан в [документации Swag](https://github.com/swaggo/swag#declarative-comments-format).

Swagger охватывает зарегистрированные CRUD-маршруты. Пустые обработчики списков
вопросов и ответов и методы репозитория без HTTP-маршрутов не включены. Авторизация описана выше; игровые и WebSocket API сюда не входят.

## API редактора

- `POST /api/quizzes` теперь возвращает созданный `QuizResponse` с ID и заголовок
  `Location`, а не пустое тело. Форма запроса не изменилась.
- `GET /api/me`: проверенный текущий пользователь.
- `GET /api/me/quizzes`: компактный список с `question_count`, `updated_at`, `revision`.
- `GET /api/quizzes/{id}/content`: публичное содержимое с временем и порядком ответов.
- `GET /api/quizzes/{id}/author`: авторское содержимое с `is_correct`, `Cache-Control: no-store`.
- `PUT /api/quizzes/{id}/content`: транзакционное сохранение всей структуры.
- `DELETE /api/quizzes/{id}`: удаление квиза с вопросами и ответами.
- `POST /api/images`: multipart с полем `file`, PNG/JPEG до 5 MiB, до 20 мегапикселей.
  Файл сохраняется в S3, ответ `{id, url}` содержит подписанную ссылку.
- `GET /api/images/{id}`: `307` на подписанную S3-ссылку, `Cache-Control: no-store`.
- `GET /api/images/{id}/url`: `{id, url}` со свежей подписанной ссылкой, `Cache-Control: no-store`.
- `DELETE /api/images/{id}`: удаление своей неиспользуемой загрузки; `409`, если привязана.

Сохранение принимает `title`, `revision`, `questions`. Порядок массивов задаёт
порядок вопросов и ответов. Существующие ID сохраняются, `id: 0` создаёт элемент,
отсутствующий в массиве элемент удаляется. `questions: []` сохраняет пустой квиз;
отсутствующий `questions` или `null` отвергается, чтобы случайно не удалить содержимое.
Любая ошибка откатывает всю транзакцию. Передавайте последнюю серверную `revision`:
устаревшая версия возвращает `409`, без перезаписи данных.

У вопросов должны быть 2–8 заполненных ответов и ровно один правильный. Название:
1–50 символов; тексты: 1–200; до 100 вопросов. `time_limit` в секундах:
5, 10, 15, 20, 30, 45, 60, 90, 120. Картинка необязательна (`image_id: ""`).
Ответ содержит актуальный квиз и новые ID. Идентификаторы должны принадлежать
редактируемому квизу/вопросу, загруженные картинки — текущему автору.

Старые индивидуальные POST вопросов и ответов сохраняют прежний контракт с пустым `201`.
Frontend создаёт эти элементы внутри общей операции сохранения и получает их ID из неё.
Миграция `0002_editor.sql` добавляет метаданные, время, порядок ответов, содержимое
изображений (прежнее хранение), каскадное удаление и отложенную проверку уникальности позиций вопросов.
Изменения через старые операции также обновляют дату и ревизию квиза.

Миграция `0003_s3_images.sql` оставляет в `images` только `id` и `author_id`.
При старте Go API переносит прежние BYTEA-файлы в S3 до удаления бинарных колонок.
Настройки S3 и порядок перехода описаны в корневом [README](../README.md#изображения-в-s3).

В `GET /quizzes/{id}/content`, `GET /quizzes/{id}/author` и ответе сохранения
у вопроса есть `image_id` и вычисляемый `image_url`. URL имеет ограниченный срок
действия; его можно обновить через `GET /images/{id}/url`. В запросе сохранения
передавайте `image_id`, без `image_url`; присланный URL не сохраняется и не используется.
При недоступном/ненастроенном S3 операции с изображениями возвращают `503`.
